# Компилятор Pawn AMXX Nova

[![License](https://img.shields.io/badge/license-GPL--3.0-blue.svg)](https://www.gnu.org/licenses/gpl-3.0)
[![Latest Release](https://img.shields.io/github/v/release/hlds-run/amxx-nova-pc)](https://github.com/hlds-run/amxx-nova-pc/releases/latest)

Современный кроссплатформенный компилятор языка Pawn для AMX Mod X. Это консольная утилита (`amxxpc`), которая компилирует исходный код Pawn (`.sma`) в исполняемые плагины (`.amxx`).

## О проекте

`AMXX Nova Pawn Compiler` — это форк и значительная переработка стандартного компилятора, поставляемого с AMX Mod X 1.9.0 / 1.10.0. Основная цель этого проекта — модернизировать кодовую базу, оптимизировать процесс сборки и обеспечить полную совместимость с существующими плагинами и стандартами AMXX.

Проект был переписан с использованием C++23 и современной системы сборки CMake, что обеспечивает простую компиляцию как на Windows, так и на Linux, а также интеграцию современных инструментов для поддержания высокого качества кода.

## Ключевые особенности

*   **Полная совместимость**: Скомпилированные плагины на 100% совместимы с официальными версиями AMX Mod X. Ваш существующий код будет работать без каких-либо изменений.
*   **Кроссплатформенность**: Компилятор можно нативно собирать и запускать как на Windows, так и на Linux.
*   **Современная кодовая база**: Осуществлён переход с устаревшего C на современный C++23 для повышения надёжности, читаемости и удобства сопровождения.
*   **Продвинутая система сборки**: Используется CMake с пресетами для унифицированной и предсказуемой сборки на любой платформе.
*   **Качество кода**: Интегрированы статические анализаторы (Clang-Tidy, Cppcheck) и форматеры (Clang-Format) для поддержания чистоты и стабильности кода.

## Использование

Компилятор является полноценной заменой стандартного `amxxpc`.

**Простая компиляция:**
```bash
amxxpc my_plugin.sma
```
Эта команда создаст файл `my_plugin.amxx` в той же директории.

**Указание пути для выходного файла:**
```bash
amxxpc my_plugin.sma -oaddons/amxmodx/plugins/my_plugin.amxx
```

**Указание директорий с заголовочными файлами:**
```bash
amxxpc my_plugin.sma -i/path/to/scripting/include -i/path/to/custom/includes
```

Ниже приведен полный список поддерживаемых опций командной строки. Полный список опций также можно вывести в терминале, запустив компилятор с ключом `--help`.

```
Опции:
        -A<число>     Выравнивание сегмента данных и стека в байтах. Значение должно быть степенью двойки.
        -a            Сгенерировать читаемый ассемблерный листинг (.asm) вместо бинарного файла (.amxx). 
                      Полезно для низкоуровневой отладки.
        -C[+/-]       Включить/выключить (+/-) компактное кодирование для уменьшения размера выходного файла.
        -c<имя>       Имя или номер кодовой страницы исходного файла (например, 1252 для Windows Latin-1).
        -D<путь>      Установить рабочую директорию компилятора. Влияет на то, как разрешаются относительные пути.
        
        -d0           Отключить отладочную информацию и проверки. Для максимальной производительности (релиз).
        -d1           [По умолчанию] Включить только проверки времени выполнения (выход за пределы массивов и т.д.).
        -d2           Включить полную отладочную информацию и проверки. Рекомендуется для разработки.
        -d3           То же, что и -d2, но с отключением оптимизаций. Полезно для пошаговой отладки.
        
        -e<имя>       Перенаправить все ошибки и предупреждения в указанный файл. Удобно для интеграции с IDE
                      и системами автоматической сборки.
        -H<hwnd>      Дескриптор окна (HWND) для отправки уведомления по завершении компиляции (для Windows).
        -i<путь>      Добавить путь для поиска заголовочных файлов (#include <... A.I.>). Можно указывать несколько раз.
                      Пути с пробелами необходимо заключать в кавычки.
        -l            Создать листинг-файл (.lst), показывающий код после обработки препроцессором
                      (#include, #define). Компиляция при этом не производится.
        -o<имя>       Установить базовое имя/путь для выходного файла. Если не указано, имя наследуется
                      от исходного файла.
        -p<имя>       Указать "файл-префикс", который будет неявно подключен в начало каждого компилируемого
                      скрипта. Удобно для глобальных констант или макросов.
        -r[имя]       Создать отчёт о перекрёстных ссылках (.xml) об использовании символов. Если имя файла
                      не указано, отчёт будет выведен в консоль.
        -sui[+/-]     Показать/скрыть (+/-) информацию об использовании стека после успешной компиляции.
```

## Сборка из исходного кода

### Требования

**Linux (Debian-подобные дистрибутивы, например, Ubuntu, Debian):**
*   Требуется поддержка multi-arch для сборки 32-битных приложений на 64-битной системе.
*   Необходимые пакеты: `build-essential`, `gcc-multilib`, `g++-multilib`, `cmake`, `ninja-build`.
    ```bash
    sudo apt-get update
    sudo apt-get install -y build-essential gcc-multilib g++-multilib cmake ninja-build git
    ```

**Windows:**
*   Visual Studio 2022 (с рабочей нагрузкой «Разработка классических приложений на C++»).
*   [CMake](https://cmake.org/download/) (версия 3.21+).
*   [Ninja Build](https://github.com/ninja-build/ninja/releases) (рекомендуется, добавьте в `PATH`).

### Инструкции по сборке

Мы предоставляем удобные скрипты для сборки в директории `tools`.

#### Linux

1.  Клонируйте репозиторий:
    ```bash
    git clone https://github.com/hlds-run/amxx-nova-pc.git
    cd amxx-nova-pc
    ```
2.  Сделайте скрипт сборки исполняемым:
    ```bash
    chmod +x tools/linux/build.sh
    ```
3.  Запустите сборку:
    ```bash
    ./tools/linux/build.sh
    ```
    *Для сборки Debug-версии используйте флаг `-b Debug`.*

#### Windows (PowerShell)

1.  Клонируйте репозиторий:
    ```bash
    git clone https://github.com/hlds-run/amxx-nova-pc.git
    cd amxx-nova-pc
    ```
2.  Запустите сборку:
    ```powershell
    .\tools\windows\build.ps1
    ```
    *Для сборки Debug-версии используйте флаг `-b Debug`.*

### Артефакты сборки

Скомпилированные бинарные файлы (`amxxpc` и `amxxpc32.so`/`amxxpc32.dll`) будут находиться в директории `bin/`, во вложенной папке, соответствующей компилятору и типу сборки (например, `bin/gcc-Release`).
