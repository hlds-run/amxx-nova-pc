Современный кроссплатформенный компилятор языка Pawn для AMX Mod X. Это консольная утилита (`amxxpc`), которая компилирует исходный код Pawn (`.sma`) в исполняемые плагины (`.amxx`).

## О проекте

`AMXX Nova Pawn Compiler` — это форк и значительная переработка стандартного компилятора, поставляемого с AMX Mod X 1.9.0 / 1.10.0. Основная цель этого проекта — модернизировать кодовую базу, оптимизировать процесс сборки и обеспечить полную совместимость с существующими плагинами и стандартами AMXX.

Проект был переписан с использованием C++23 и современной системы сборки CMake, что обеспечивает простую компиляцию как на Windows, так и на Linux, а также интеграцию современных инструментов для поддержания высокого качества кода.

## Ключевые особенности

*   **Полная совместимость**: Проект сохраняет оригинальное ядро компилятора Pawn из AMX Mod X, что гарантирует 100% совместимость скомпилированных плагинов (.amxx) и избавляет от необходимости вносить какие-либо изменения в существующий исходный код (.sma).
*   **Кроссплатформенность**: Компилятор можно нативно собирать и запускать как на Windows, так и на Linux.
*   **Современная архитектура и обвязка**: Оболочка командной строки (`amxxpc`) и система сборки проекта были полностью переписаны на современном C++23 с использованием CMake. Это обеспечивает кроссплатформенность и простоту сборки, сохраняя при этом оригинальное, проверенное временем ядро компилятора.
*   **Качество кода**: Интегрированы статические анализаторы (Clang-Tidy, Cppcheck, PVS-Studio, IWYU) и форматеры (Clang-Format) для поддержания чистоты и стабильности кода.

## Использование

Компилятор является полноценной заменой стандартного `amxxpc` и предлагает гибкие способы настройки.

### Основы компиляции

**Простая компиляция:**
```bash
amxxpc my_plugin.sma
```
Эта команда создаст файл `my_plugin.amxx` в текущей рабочей директории (используйте опцию `-o`, чтобы изменить место вывода).

**Указание пути для выходного файла:**
```bash
amxxpc my_plugin.sma -oaddons/amxmodx/plugins/my_plugin.amxx
```

**Указание директорий с инклудами:**
```bash
amxxpc my_plugin.sma -i/path/to/scripting/include -i/path/to/custom/includes
```

```

        -r[имя]       Создать отчёт о перекрёстных ссылках (.xml) об использовании символов.
```

### Файлы конфигурации (.cfg)

Чтобы избежать длинных и повторяющихся команд, вы можете задавать опции компилятора в `.cfg` файлах. Каждая строка файла содержит одну опцию; строки, начинающиеся с `#`, считаются комментариями. Это особенно удобно для управления различными профилями сборки (например, `debug` и `release`).

**Загрузка конфигурации:**

1.  **Явное указание (`-T`)**: Используйте опцию `-T` для загрузки одного или нескольких файлов конфигурации (опцию можно указывать несколько раз).
    *   `amxxpc -T D:\configs\my_build.cfg ...` — загрузит файл по полному пути (файл должен существовать).
    *   `amxxpc -T release ...` — будет искать файл `<папка_компилятора>/target/release.cfg` (к имени без расширения автоматически добавляется `.cfg`).

2.  **Загрузка по умолчанию** (если `-T` не указан):
    *   Компилятор ищет `<папка_компилятора>/target/default.cfg`.
    *   Если не найден, ищет `pawn.cfg` рядом с исполняемым файлом компилятора.

> [!NOTE]
> Независимо от перечисленного выше, ядро компилятора дополнительно загружает `<папка_компилятора>/target/default.cfg` при запуске. Если такой файл существует, его опции применяются даже при явном выборе файла через `-T`.

**Приоритет опций:** Опции применяются в следующем порядке: сначала из командной строки, затем из `.cfg` файла(-ов). Для опций, принимающих одно значение (например, `-d`, `-o`), **значение из `.cfg` файла переопределяет значение командной строки**. Опции, которые можно указывать многократно (например, `-i`), объединяются из всех источников. Определения констант и макросов (`sym=значение`), заданные в командной строке, всегда имеют приоритет над определениями из файла.

### Определение констант и макросов

Вы можете определять константы и макросы напрямую из командной строки, что идеально подходит для сборочных скриптов.

*   **Числовая константа**: `BUILD_ID=512`
*   **Строковый макрос**: `VERSION_NAME="1.5.0 Release"` (эквивалентно `#define VERSION_NAME "1.5.0 Release"`)
*   **Флаг для условной компиляции**: `DEBUG_MODE=` (определяет `DEBUG_MODE` как константу `1`)

**Пример комплексной команды:**
```bash
amxxpc DEBUG_MODE= BUILD_ID=512 VERSION_NAME="1.5.0 Beta" my_plugin.sma
```

## Сборка из исходного кода

### Требования

**Linux (Debian-подобные дистрибутивы, например, Ubuntu, Debian):**
*   Требуется поддержка multi-arch для сборки 32-битных приложений на 64-битной системе.
*   Необходимые пакеты: `build-essential`, `gcc-multilib`, `g++-multilib`, `cmake`, `ninja-build`.
    ```bash
    sudo apt-get update
    sudo apt-get install -y build-essential gcc-multilib g++-multilib cmake ninja-build git
    ```
*   При сборке GCC по умолчанию используется линкер Gold (`ld.gold`); если этап линковки завершается ошибкой, установите пакет `binutils-gold`.

**Windows:**
*   Visual Studio 2022 (с рабочей нагрузкой «Разработка классических приложений на C++»).
*   [CMake](https://cmake.org/download/) (версия 3.21+).
*   [Ninja Build](https://github.com/ninja-build/ninja/releases) (рекомендуется, добавьте в `PATH`).

**Альтернатива:** готовый Dev Container для VS Code (Ubuntu 24.04 с предустановленными GCC, Clang и Cppcheck) находится в `.devcontainer/`.

### Инструкции по сборке

Мы предоставляем удобные скрипты для сборки в директории `tools`. Оба скрипта поддерживают дополнительные флаги: `-c` (компилятор: `gcc`/`clang` на Linux, `msvc`/`clang` на Windows), `-j` (число параллельных задач), `-k` (сохранять директорию сборки между запусками), `-s` (статическая линковка рантайма), `-g` (генератор, только Windows) — а также передают любые дополнительные аргументы CMake после `--`.

#### Linux

1.  Клонируйте репозиторий:
    ```bash
    git clone https://github.com/hlds-run/amxx-nova-pc.git
    cd amxx-nova-pc
    ```
2.  Сделайте скрипт сборки исполняемым:
    ```bash
    chmod +x tools/linux/build.sh
    ```
3.  Запустите сборку:
    ```bash
    ./tools/linux/build.sh
    ```
    *Тип сборки задаётся флагом `-b`: `Release` (по умолчанию), `Debug` или `RelWithDebInfo`.*

#### Windows (PowerShell)

1.  Клонируйте репозиторий:
    ```bash
    git clone https://github.com/hlds-run/amxx-nova-pc.git
    cd amxx-nova-pc
    ```
2.  Запустите сборку:
    ```powershell
    .\tools\windows\build.ps1
    ```
    *Тип сборки задаётся флагом `-b`: `Release` (по умолчанию), `Debug` или `RelWithDebInfo`.*

### Артефакты сборки

Скомпилированный бинарный файл `amxxpc` (со статически линкованным 32-битным ядром компилятора) будет находиться в директории `bin/`, во вложенной папке, названной по инструментарию и типу сборки (например, `bin/GNU-Release` для GCC на Linux или `bin/MSVC-Release` для Visual Studio на Windows).

## Участие в проекте

Именно благодаря вкладу сообщества открытый исходный код является такой потрясающей средой для обучения, вдохновения и творчества. Любой ваш вклад будет **высоко оценен**.

1.  Сделайте форк проекта.
2.  Создайте свою ветку для новой функциональности (`git checkout -b feature/AmazingFeature`).
3.  Закоммитьте ваши изменения (`git commit -m 'Add some AmazingFeature'`).
4.  Отправьте изменения в ветку (`git push origin feature/AmazingFeature`).
5.  Создайте Pull Request.

Пожалуйста, придерживайтесь стиля кода, определённого в файле `.clang-format`. Хук pre-commit для форматирования (использует поставляемые в `tools/` бинарники `clang-format-20`) устанавливается автоматически при конфигурировании проекта через CMake.

В проекте также есть модульные тесты на базе [GoogleTest](https://github.com/google/googletest): соберите проект с `-D BUILD_UNIT_TESTS=ON` (фреймворк скачивается на этапе конфигурирования) и запустите цель `amxxpc.test`.
